# Техническое задание на разработку персонального сайта-портфолио

> Статус документа: черновик для согласования  
> Версия: 1.0  
> Дата: 3 октября 2026 года

## 1. Общая информация

Необходимо разработать современный персональный сайт-портфолио с выразительным авторским дизайном, интерактивными элементами и административной панелью.

Сайт должен не просто демонстрировать проекты, а создавать полноценный визуальный опыт: производить сильное первое впечатление, подчёркивать профессиональный уровень владельца и мотивировать посетителя связаться с ним.

## 2. Цели проекта

- Презентовать владельца сайта, его опыт, специализацию и профессиональный подход.
- Показать лучшие работы в формате полноценных кейсов.
- Сформировать узнаваемый персональный образ.
- Повысить доверие потенциальных клиентов и работодателей.
- Получать заявки на сотрудничество через сайт.
- Обеспечить самостоятельное управление контентом через административную панель.
- Создать техническую основу для дальнейшего развития сайта.

## 3. Целевая аудитория

- Потенциальные клиенты.
- Работодатели и рекрутеры.
- Представители агентств и студий.
- Партнёры и специалисты из смежных областей.
- Посетители, которые знакомятся с работами автора по внешней ссылке.

## 4. Визуальная концепция

### 4.1. Общий стиль

Визуальное направление: **premium digital / editorial design / controlled brutalism**.

Дизайн должен выглядеть как работа сильной международной digital-студии: современно, дорого, нестандартно и узнаваемо.

### 4.2. Основные визуальные приёмы

- Крупная выразительная типографика.
- Контрастные заголовки.
- Асимметричная модульная сетка.
- Полноэкранные композиции.
- Тёмная или нейтральная основа с одним ярким акцентным цветом.
- Крупные изображения и видео проектов.
- Минимальное количество визуального шума.
- Авторские микроанимации.
- Плавные переходы между страницами.
- Необычные состояния наведения.
- Интерактивный курсор на настольных устройствах.
- Отдельные 3D- или WebGL-элементы при наличии художественной необходимости.

Все эффекты должны усиливать впечатление от контента, не ухудшая читаемость, навигацию и скорость загрузки.

### 4.3. Дизайн-система

Необходимо подготовить единую дизайн-систему:

- цветовая палитра;
- набор шрифтов и типографическая шкала;
- правила отступов и сетка;
- кнопки и ссылки;
- карточки проектов;
- элементы форм;
- навигация;
- состояния загрузки;
- hover-, focus-, active- и disabled-состояния;
- правила использования анимаций;
- компоненты для вывода контента из административной панели.

## 5. Структура сайта

### 5.1. Главная страница

#### Первый экран

Первый экран должен содержать:

- имя и фамилию;
- профессию или специализацию;
- короткий сильный слоган;
- интерактивный визуальный объект, видео или авторскую композицию;
- кнопку «Смотреть проекты»;
- кнопку «Связаться»;
- индикатор прокрутки;
- текущий статус доступности для новых проектов.

Пример позиционирования:

> Я создаю цифровые продукты и визуальные решения, которые невозможно не заметить.

#### Остальные блоки

1. Краткая информация об авторе.
2. Избранные проекты.
3. Основные направления работы.
4. Опыт, клиенты и достижения.
5. Отзывы.
6. Призыв к сотрудничеству.
7. Контакты и ссылки на социальные сети.

### 5.2. Страница «Обо мне»

Страница должна содержать:

- фотографию или авторский визуальный образ;
- полное имя;
- профессию и специализацию;
- подробную биографию;
- профессиональную философию;
- основные навыки;
- опыт работы;
- образование при необходимости;
- достижения и награды;
- список клиентов или компаний;
- используемые инструменты и технологии;
- языки;
- город и часовой пояс;
- текущий статус доступности;
- кнопку скачивания резюме;
- ссылку на раздел контактов.

Опыт работы может быть представлен в формате интерактивной временной шкалы.

### 5.3. Страница «Проекты»

Страница представляет собой каталог работ.

Для каждого проекта выводятся:

- обложка;
- название;
- категория;
- год;
- краткое описание;
- роль автора;
- основные технологии или инструменты;
- ссылка на подробный кейс.

Необходимо реализовать:

- фильтрацию по категориям;
- плавное изменение списка без перезагрузки страницы;
- управление порядком проектов из административной панели;
- отдельное выделение избранных проектов;
- адаптивное отображение карточек;
- возможность скрыть проект без его удаления.

Предварительный набор категорий:

- Все проекты.
- Дизайн.
- Разработка.
- Брендинг.
- Личные проекты.
- Эксперименты.

Категории должны создаваться и редактироваться через административную панель.

### 5.4. Страница проекта

Каждый проект должен быть оформлен как самостоятельный визуальный кейс.

Рекомендуемая структура:

1. Полноэкранная обложка.
2. Название и краткое описание.
3. Клиент, категория и год.
4. Поставленная задача.
5. Роль автора и зона ответственности.
6. Процесс работы.
7. Концепция и принятые решения.
8. Галерея изображений.
9. Видео или интерактивные материалы.
10. Использованные технологии и инструменты.
11. Результаты и измеримые показатели.
12. Отзыв клиента.
13. Ссылки на опубликованный проект.
14. Переход к следующему кейсу.

Контент страницы проекта должен собираться в административной панели из отдельных блоков:

- текст;
- заголовок;
- изображение;
- полноэкранное изображение;
- галерея;
- видео;
- цитата;
- статистика;
- список;
- блок «до/после»;
- две колонки;
- внешняя ссылка;
- разделитель или отступ.

### 5.5. Страница «Услуги»

Для каждой услуги необходимо указать:

- название;
- краткое описание;
- состав работ;
- этапы сотрудничества;
- ориентировочный срок;
- стоимость «от» либо предложение запросить расчёт;
- связанные проекты;
- кнопку отправки заявки.

### 5.6. Страница «Контакты»

Необходимо разместить:

- email;
- телефон;
- Telegram;
- WhatsApp при необходимости;
- GitHub;
- Behance;
- Dribbble;
- LinkedIn;
- другие социальные сети;
- город и часовой пояс;
- статус доступности для проектов;
- форму обратной связи.

Все контактные данные должны редактироваться через административную панель.

### 5.7. Форма обратной связи

Поля формы:

- имя;
- email, телефон или ник в мессенджере;
- название компании;
- тип проекта;
- описание задачи;
- предполагаемый бюджет;
- желаемые сроки;
- возможность прикрепить файл;
- согласие на обработку персональных данных.

После отправки заявки необходимо:

- показать посетителю сообщение об успешной отправке;
- сохранить заявку в административной панели;
- отправить уведомление на email;
- при необходимости отправить уведомление в Telegram;
- защитить форму от спама и автоматических отправок.

### 5.8. Дополнительные страницы

- Авторская страница ошибки 404.
- Политика конфиденциальности.
- Согласие на обработку персональных данных.
- Страница благодарности после отправки формы.

## 6. Навигация

Основное меню:

- Главная.
- Обо мне.
- Проекты.
- Услуги.
- Контакты.

Требования:

- меню доступно на всех страницах;
- активный раздел визуально выделяется;
- мобильное меню открывается на весь экран;
- должна быть доступна быстрая кнопка перехода к контактам;
- логотип или имя автора возвращает пользователя на главную страницу;
- переходы между страницами сопровождаются плавной анимацией;
- навигация должна полностью поддерживать управление с клавиатуры.

## 7. Административная панель

### 7.1. Авторизация

- Вход по email и паролю.
- Восстановление пароля.
- Защита административных маршрутов.
- Возможность включения двухфакторной авторизации.
- Автоматическое завершение неактивной сессии.

### 7.2. Управление контентом

Через административную панель владелец должен иметь возможность:

- редактировать главную страницу;
- редактировать раздел «Обо мне»;
- создавать, редактировать и удалять проекты;
- сохранять проекты как черновики;
- публиковать и снимать проекты с публикации;
- менять порядок проектов;
- закреплять избранные проекты;
- создавать и редактировать категории;
- собирать кейсы из контентных блоков;
- добавлять услуги;
- добавлять клиентов и отзывы;
- редактировать контакты и социальные сети;
- загружать и заменять резюме;
- управлять файлами и изображениями;
- изменять SEO-параметры страниц;
- просматривать входящие заявки.

### 7.3. Дополнительные возможности

- Предварительный просмотр перед публикацией.
- Автосохранение черновиков.
- Автоматическая оптимизация изображений.
- Валидация обязательных полей.
- Журнал изменений.
- Резервное копирование данных.
- Отображение даты создания и последнего изменения материала.

## 8. Анимации и интерактивность

Предусмотреть:

- авторский прелоадер;
- плавные переходы между страницами;
- анимации появления контента при прокрутке;
- параллакс для отдельных элементов;
- эффект магнитных кнопок;
- изменение курсора над интерактивными элементами;
- анимированное раскрытие меню;
- горизонтальные секции при художественной необходимости;
- полноэкранное раскрытие изображений;
- анимацию текста по словам или строкам;
- переход между соседними проектами;
- деликатную реакцию элементов на движение указателя.

Требования к анимациям:

- не мешать чтению и навигации;
- поддерживать стабильную частоту кадров;
- автоматически упрощаться на слабых и мобильных устройствах;
- учитывать системную настройку `prefers-reduced-motion`;
- не блокировать доступ к контенту при ошибке загрузки анимационного модуля.

## 9. Адаптивность

Сайт должен корректно работать на:

- широкоформатных мониторах;
- стандартных настольных мониторах;
- ноутбуках;
- планшетах;
- смартфонах.

Мобильная версия должна быть спроектирована отдельно, а не являться механически уменьшенной копией десктопной версии.

На мобильных устройствах необходимо:

- упрощать ресурсоёмкие эффекты;
- сохранять выразительную типографику;
- обеспечивать удобный размер интерактивных элементов;
- исключить горизонтальную прокрутку интерфейса;
- выводить полноэкранное мобильное меню;
- загружать изображения подходящего размера;
- учитывать безопасные области экранов устройств.

## 10. Техническая реализация

### 10.1. Рекомендуемый стек

- **Frontend:** Next.js и TypeScript.
- **Стили:** Tailwind CSS, CSS Modules или другая согласованная система.
- **Анимации:** Framer Motion и/или GSAP.
- **3D-графика:** Three.js только для обоснованных визуальных эффектов.
- **CMS:** Sanity, Strapi либо собственная административная панель.
- **База данных:** PostgreSQL или управляемая облачная база данных.
- **Хранение медиа:** S3-совместимое или специализированное облачное хранилище.
- **Размещение:** Vercel или аналогичная платформа.

Окончательный стек выбирается после согласования бюджета, сроков и требований к размещению данных.

### 10.2. Архитектурные требования

- Компонентная архитектура.
- Строгая типизация данных.
- Отделение контента от визуального представления.
- Возможность добавления новых типов контентных блоков.
- Возможность подключения английской версии.
- Возможность добавить блог без полной переработки сайта.
- Возможность создавать закрытые кейсы с доступом по паролю.
- Возможность переноса проекта на другой сервер или аккаунт.

## 11. Производительность

Необходимо реализовать:

- быструю загрузку первого экрана;
- форматы изображений WebP и AVIF;
- адаптивные размеры изображений;
- отложенную загрузку некритичных медиа;
- автоматическое сжатие загружаемых файлов;
- предварительную загрузку критических шрифтов;
- минимизацию JavaScript, загружаемого при первом открытии;
- отсутствие заметных скачков интерфейса;
- кэширование статических данных;
- корректное отображение сайта при медленном интернете.

Целевые показатели Lighthouse для основных страниц:

| Категория | Целевое значение |
|---|---:|
| Performance | 90+ |
| Accessibility | 95+ |
| Best Practices | 95+ |
| SEO | 95+ |

Для страниц с тяжёлой WebGL-графикой показатель производительности согласовывается отдельно.

## 12. SEO

Необходимо реализовать:

- редактируемые `title` и `description`;
- человекопонятные URL;
- индивидуальные SEO-настройки для проектов;
- Open Graph-изображения;
- корректные превью ссылок в социальных сетях и мессенджерах;
- `sitemap.xml`;
- `robots.txt`;
- canonical-ссылки;
- структурированные данные Schema.org;
- `alt`-тексты для изображений;
- фавиконки и иконки для устройств;
- страницу 404;
- редиректы при изменении URL опубликованных материалов.

## 13. Аналитика

Предусмотреть подключение систем веб-аналитики.

Необходимо отслеживать:

- просмотры страниц;
- просмотры проектов;
- клики по контактам;
- скачивание резюме;
- отправку формы;
- переходы по внешним ссылкам;
- ошибки отправки формы;
- основные показатели производительности.

Конкретные сервисы аналитики определяются перед запуском.

## 14. Доступность

- Семантическая HTML-разметка.
- Полная навигация с клавиатуры.
- Видимые focus-состояния.
- Достаточная контрастность текста и интерфейса.
- Текстовые альтернативы для значимых изображений.
- Подписи для полей форм.
- Корректная работа с программами экранного доступа.
- Возможность уменьшить интенсивность анимаций.
- Отсутствие важных функций, доступных только через hover.

## 15. Безопасность

- Работа сайта только по HTTPS.
- Защищённая авторизация в административной панели.
- Безопасное хранение паролей и секретов.
- Серверная валидация данных.
- Защита форм от спама и автоматических запросов.
- Ограничение типов и размера загружаемых файлов.
- Защита от распространённых веб-уязвимостей.
- Ограничение частоты запросов для чувствительных операций.
- Резервное копирование контента и базы данных.
- Исключение секретных ключей из клиентского кода.

## 16. Поддерживаемые браузеры

Сайт должен корректно работать в актуальных версиях:

- Google Chrome;
- Apple Safari;
- Mozilla Firefox;
- Microsoft Edge;
- мобильных браузеров iOS и Android.

Поддержка устаревших браузеров выполняется только по отдельному согласованию.
